# AI Usage & Co-Pilot Disclosure

## Overview
This document transparently outlines the assistance provided by AI tooling (specifically Antigravity, Google DeepMind's advanced agentic coding assistant) during the design, implementation, and verification of the Aurik Tech Lead Assessment submission.

---

## 1. Areas Where AI Was Used

1. **Repetitive Boilerplate Generation**:
   - Initial generation of repetitive vendor CSV mapping functions, Pydantic v2 schemas, and standard SQLAlchemy model declarations.
   - Comprehensive test case scaffolding across 135 unit, property, and integration tests.
2. **Deterministic Engine Exploration**:
   - Verification of edge cases in time-window evaluations (e.g. cross-vendor conflict windows, recovery signals clearing prior alerts).
   - Drafting property-based shuffle tests to guarantee order-independence of the pure functional status engine.
3. **OpenAPI & Documentation Structuring**:
   - Generating standard OpenAPI 3.1 definitions and Postman Collection v2.1.0 JSON schemas from FastAPI endpoint signatures.
   - Structuring Markdown tables for the engine rules catalog and data lineage tracking.

---

## 2. Areas Driven Strictly by Human Engineering Direction

1. **Architectural & Design Choices**:
   - Choosing PostgreSQL `FOR UPDATE SKIP LOCKED` over external message brokers (Kafka/RabbitMQ) for atomic, single-transaction ingestion guarantees.
   - Establishing the **Two-Layer Idempotency Model** (Layer 1 canonical JSON hash at gateway vs. Layer 2 semantic content hash in normalization worker).
   - Directing the pure functional design of `evaluate_machine_state(...)` without database or clock side-effects to enable point-in-time time-travel querying (`as_of`).
2. **Domain Rules & Anchor Expectations**:
   - Defining the resolution rule for `EQ-006`: `SENSOR_DEGRADED` signals on dimension `SENSOR` strictly contribute maximum attention 1, producing `LOW_SIGNAL_TRUST`, keeping `EQ-006` in `WATCH`, attention 1, `needs_attention = false`.
   - Establishing the operational thresholds: vibration > 85% of rated max, temperature > 90% of rated max, idle power de-escalation, and under-maintenance suppression.
3. **Verification & Quality Bar**:
   - Requiring zero stubbed code, no broad `except Exception: pass`, strict type hints (`mypy` passing on all 46 files), and 100% clean linter checks (`ruff`).

---

## 3. Human Review & Verification Methodology

Every line of code and test case generated by or with AI was subjected to strict verification:
1. **Automated Static Analysis**: Run `ruff check .` and `mypy app/ tests/` in strict mode to ensure zero type coercion gaps, unused imports, or lint violations.
2. **Anchor Reconciliation**: Verified that the seed pipeline reproduces the exact anchor expectations for machines `EQ-001` through `EQ-008` as of `2026-04-18T09:00:00Z`.
3. **Property Testing**: Tested permutation invariance by shuffling signal arrival order 10 consecutive times to prove that derived equipment statuses are strictly deterministic.
